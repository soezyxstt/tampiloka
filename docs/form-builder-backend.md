# Form builder backend contract

Backend uses `CMS_DATABASE_URL` exclusively. `lib/db/schema.ts` exports `forms`, `formRevisions`, `formSlugs`, `submissions`, `assets`, and `submissionFiles`. Storage lane: assets have `id`, `formId`, `ownerId`, `uploadSessionId`, `objectKey`, `filename`, `contentType`, `size`, `state` (`pending`, `uploaded`, `attached`), and timestamps. Public files must have the same form ID and upload session ID and be marked `uploaded` after storage verification before submission. Admin assets use ownerId and null uploadSessionId. Never expose objectKey in public responses.

Auth exports `getAdminSession()` and `requireAdmin()` from `lib/auth` (both accept optional Headers); a valid verified-email session must still be on `ADMIN_EMAIL_ALLOWLIST`. `requireAdmin` throws for unauthorized requests.

Assets now also expose nullable revisionId and questionId. Public uploads must set both to the published revision and file question; submission checks them. Use @tanstack/react-table v8 root exports. @aws-sdk/s3-presigned-post is being installed.

Migration: from `apps/tampiloka`, set only the dedicated CMS `CMS_DATABASE_URL`, then run `node node_modules/drizzle-kit/bin.cjs migrate` (or `pnpm exec drizzle-kit migrate` in a properly installed workspace). Review the SQL and target before execution; no schema push. Migration generation completed locally; it has not been applied by this lane.

Required runtime environment: `CMS_DATABASE_URL`, `BETTER_AUTH_URL` (exact site origin), `BETTER_AUTH_SECRET` (at least 32 characters), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and comma-separated `ADMIN_EMAIL_ALLOWLIST`; storage variables are documented by the infrastructure lane. Missing auth configuration disables auth rather than granting access. Add the verified Google OAuth callback `https://tampiloka.site/api/auth/callback/google` to the Google client. All listed emails are owners of their own forms; existing users cease to be authorized when removed from the allowlist. Historical submissions and private objects are retained after soft deletion. No automated cleanup or malware scanner is implemented by this lane.

Public responses must bind uploaded files to the exact form, revision, question and session; uploaded objects are HEAD checked again on submission. Publish checks image references against uploaded admin-owned assets for the same form. Duplication copies schema IDs and therefore image references must be replaced with assets owned by the new form before publishing. Slug aliases remain reserved and resolve to the latest canonical slug. Draft updates require expectedVersion. Read responses include their immutable revision schema.

Verification: `node --experimental-strip-types --test scripts/form-backend.test.mjs`; no live OAuth, migration, storage integration, or end-to-end lifecycle test has been completed by this lane. Files from other lanes may still be in flight; run the full typecheck and integration suite after reconciliation.

Response administration: `GET /api/admin/forms/[id]/responses` includes `status` (`active` or `archived`) and omits soft-deleted records. `POST /api/admin/forms/[id]/responses/[submissionId]` accepts JSON `{ "action": "archive" | "restore" | "delete" }`, requires the form owner and same origin, and returns `{ submission: { id, status } }`. Delete is a soft delete: answers, idempotency records and objects remain stored for future retention/cleanup work; associated assets are marked deleted so new download URLs cannot be issued. Previously issued short-lived URLs remain usable until expiration. All accepted submissions, including archived/deleted ones, count toward the published response limit. The current response table has no controls for these endpoints yet.

`settings.maxResponses` and `settings.closesAt` are read from the published revision. New submissions check them while holding the form row lock, after checking canonical idempotent replay. Public GET returns 410 when either limit is reached. Limits apply to the lifetime accepted submission count for the form across revisions.
