# Form builder core contract

Import from `@/lib/forms/schema`. `formSchema` is the strict, bounded Zod parser for drafts/revisions; use its parsed output. IDs for sections, questions, options, rows and columns are globally unique. `createBlankForm()` and `weddingTemplate()` create fresh durable IDs. `normalizeSlug()` and `isValidSlug()` are separate: normalize user suggestions, reject invalid/reserved values and enforce uniqueness/alias policy in persistence.

`getVisibleSections(schema, answers)` follows forward-only `section.routing = { questionId, choices: { [optionId]: targetSectionId }, defaultSectionId? }`; without a matching target, continue to the next section. The route question must be a single choice or dropdown in that section. Skipped sections remain excluded even if their answers were submitted.

`validateAnswers(schema, input)` returns `{ success, answers, fieldErrors }`; persist only `answers` on success. Unknown question IDs are errors. Hidden answers are discarded, not persisted. Text, date/time and choice answers are strings; numbers, scales and ratings are numbers; multiple choice and files are arrays of IDs; grids are `{ [rowId]: columnId }` or `{ [rowId]: columnId[] }`. Other answers use `other:<text>` as a choice ID only when `allowOther` is true; text is limited to 500 characters. File IDs are references only: the service MUST independently verify ownership, session, state, actual object content type/size and count against published validation settings before attachment. Schema validation does not authorize assets or scan uploads.

Validation settings: `minLength`, `maxLength`, `min`, `max`, `minSelections`, `maxSelections`, `minDate`, `maxDate`, `allowedTypes`, `maxFileSize` (bytes), `maxFiles`, `message`. Dates use ISO local strings (`YYYY-MM-DD`, `HH:mm`, `YYYY-MM-DDTHH:mm`). Default scale/rating bounds are 1–5; default file count is one. Choice IDs and grid row/column IDs must match the revision. Validate the published revision, not a mutable draft. Request-body and aggregate-upload limits must also be enforced at the API boundary.

## Integration checks and remaining gates

`formSchema` accepts incomplete editor drafts (including blank labels and empty choice/grid lists), so publication requires a separate completeness check; a syntactically valid draft alone does not establish a usable published form. Renderer must implement the documented `other:` encoding and clear or ignore hidden answers. Submission retries must compare the same canonical validated answer map that was persisted: raw input may include hidden answers that validation discards, so comparing a retry's raw input directly against stored answers incorrectly rejects legitimate retries.
