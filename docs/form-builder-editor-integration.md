# Form editor integration handoff

Owned route: `/admin/forms/[id]/edit`; editor components live under `apps/tampiloka/components/admin/form-editor*`. The editor consumes `FormSchema` and the existing form APIs, uses the shared public renderer for preview, and links to the existing settings page for theme settings. Unknown settings including `maxResponses` and `closesAt` remain in the cloned draft. The renderer uses `/api/forms/assets/[id]`, whose separate owner added authenticated draft-image access. Uploads use the existing admin start, direct POST, complete protocol.

Routing is checked after edits, including deletion, type changes and section reorder. Saving is paused until an operator repairs invalid rules or uses the explicitly confirmed repair action. Repair preserves valid rules, removes only invalid references, and is undoable. Changing question type or the routing question asks before replacing associated data. Shared Base UI select controls and a searchable Base UI popover serve editor choices.

Draft saves serialize PATCH requests with `expectedVersion`, preserve later edits, store local recovery, and stop on version conflicts. Recovery must be restored or discarded before editing; stale recovery explicitly warns that it can replace newer server content. Same-origin link clicks and browser unload are guarded when edits or recovery are pending. Recovery is local to the browser profile and uses one key per form: simultaneous editor tabs may overwrite each other's local recovery. Browser history navigation within the app is not yet guarded; do not treat it as verified safe. A failed save can be retried. Slug collisions are distinct from version conflicts.

Verification: focused editor helper tests cover reorder, ID duplication and routing repairs. Editor lint and app TypeScript results are recorded in the final handoff. No browser, live API, authenticated upload, storage CORS, or end-to-end lifecycle verification was performed. Preview of newly uploaded images depends on the concurrently supplied asset endpoint and has not been exercised end to end. Local recovery has no visual diff, and unfinished uploads require selecting a file again.
