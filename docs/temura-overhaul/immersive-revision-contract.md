## Hard acceptance

- Recompose markup, not just CSS or color. Each template differs in at least four of: opening, couple, event presentation, story, gallery, closing. Use the distinct blueprint below; do not converge siblings to the same portrait/frame/section sequence.
- Remove every horizontal gallery translated by vertical scroll, every oversized sticky runway, and every template dependency on --tk-progress/--tk-drift/--tk-counter/--tk-turn. No data-scene in these sixteen renderers. Do not change the shared kit used by other previews.
- Content uses normal document flow. No fixed/minimum viewport heights on opened sections and no fixed photo stage containing text. Closed cover alone may use the viewport height including toolbar. Names, parents, dates, stories, wishes and maps must be able to grow naturally.
- Motion vocabulary: at most one coordinated opening (optional), small opacity/translate reveals via existing data-reveal observer, hover/focus or user-controlled interaction. No travelling ornaments, looping decoration, arbitrary opposite movement or scroll-derived rotations. Static ornaments remain intentional framing. Openings must not all use doors or curtains. Default is no opening overlay if a staged reveal is sufficient.
- A visible photo's content, especially heads, is never covered by ornament, shutter, caption or another image. Decoration is beneath photos/text or in a separate margin/scene zone. Layer contract: backdrop 0, ornaments 1, content 2; no decorative image above content. CSS crops/frame masks must not crop heads. Use normal 4:5 photos where masks compromise readability.
- All six gallery photos visible/reachable in normal vertical reading flow or a clearly user-controlled gallery. Default: no carousel. Every design must have a different gallery composition. Do not repeat hero+inset spreads for multiple themes.
- Preserve Nara & Aruna, existing truthful invitation data, automatic greeting, real iframe map, calendar/music/lightbox/local RSVP and honest gift helper. No fake payments. Short Indonesian functional copy, no design explanations/demo captions, slogans, overlines or extra number labels.
- Body >=14px, controls >=44px; focus visible; reduced motion stops animations and never hides content. Mobile 320/390 and desktop1440: no overflow, clear faces, bottom-nav clearance. CSS native flow handles changing content height. No manual viewport phase offsets.
- Use existing helpers/installed dependencies only. Theme-specific JSX/CSS is allowed; new generic layout engines are not. Remove obsolete CSS rather than stacking overrides. Keep each theme's CSS coherent.
- Verification: scoped TypeScript, owned TSX ESLint, PostCSS check. In report enumerate structural differences, removed scroll dependencies, and how text/gallery height can grow. Do not claim browser QA unless performed; parent owns visual QA.
